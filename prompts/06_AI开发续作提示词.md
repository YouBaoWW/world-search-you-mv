# 06 · AI 开发续作提示词（给 Claude Code / Codex 等编程助手）

> 每一条都可以直接复制给编程助手。开头那段"通用前置"每次都要带上。
> 待办编号对应 `HANDOFF.md` 第 4 节。

## 通用前置（每次都带上）

```
这是一个 Remotion 工程（world.search(you); 同人 MV，1920×1080 / 60fps）。先读 HANDOFF.md、STORYBOARD.md 和 src/ascii/timeline.js。
规则：
1. 所有画面都是时间 t 的纯函数：不能有帧间状态，不能用 Math.random() 或 Date。
2. 镜头和事件的时间一律用小节 B(n)（138.75 BPM，第一拍 0.35 秒），不要直接写秒数。
3. 歌词文字只从 public/data/lyrics.json 读取，不要把歌词写进代码。
4. 改完用 `npm run stills -- --at <相关秒数> --sheet out/check.png --cols 3` 出截图，自己看过再汇报；不要只说"应该可以了"。
5. 渲染用本机 Chrome（remotion.config.js）；用 ffmpeg-static 处理整片时要加 -threads 1。
```

## P0

**P0-1 接入立绘后的检查**
```
我把 GPT 立绘放进了 public/portraits/。检查 S13–S20 每个用到立绘的镜头（146、160、180、236、250、262 秒）：
人物朝向和斜切色带的方向是否一致、头顶有没有被画面上边裁掉、手有没有伸向画面中线。
不对的地方，调整 src/modern/scenes.jsx 里对应 <Plate> 的 x/y/w/h，不要去改图片。
同时把 GlyphPortrait 的 cols 从 58–60 提到 80，看芬妮的点阵虚影能不能更细。
```

**P0-2 中文字幕**
```
public/data/song.lrc 里已经为每句加了中文翻译（同一时间戳两行）。运行 node tools/lyrics.mjs public/data/song.lrc 重新生成 lyrics.json，
然后检查 20、66、155、164、212、240、283 秒：中文在 CRT 字幕带、字幕带、满屏字、全屏巨字、逐词大字、终端堆叠里都正常显示，不溢出、不和英文重叠。
```

**P0-3 色彩范围**
```
现在成片是 yuvj420p（full range）。改成 limited range（yuv420p tv）：优先用 Config.overrideFfmpegCommand 在编码时加 scale=in_range=full:out_range=tv 和 -color_range tv；
如果不行，就把 setVideoImageFormat 改成 'png'。先只渲染 0–10 秒和 180–190 秒验证（--frames=0-600 等），用 ffprobe 确认 color_range=tv，并对比前后截图的黑位。
```

## P2

**P2-1 逐词时间轴（强制对齐）**
```
现在每句里的词是在该句前 75% 时长里均匀分布、再吸附到八分音符的（src/modern/lyrics.jsx 的 wordsOf）。
用 @remotion/install-whisper-cpp + @remotion/openai-whisper，对 public/song.mp3 做词级时间戳识别，
再和 lyrics.json 的每句做对齐（句内按词顺序匹配，匹配不上的词退回均匀分布），写入 lyrics.json 的 words[].at。
wordsOf 有 words[].at 时优先用它。检查 156–178 秒的满屏字是否和演唱咬合。
```

**P2-2 候选卡用插画**

**P2-3 渲染提速**
```
全片渲染约 30 分钟，瓶颈在 src/ascii/display.js 的 warp()（CRT 曲面每帧约 1500 次 drawImage）。
方案一：step 从 2 改成 4，对比 10 秒和 60 秒两张截图，肉眼看不出差别就采用；方案二：曲面改成 WebGL fragment shader。
用 npx remotion benchmark 或对比渲染 0–30 秒的耗时来汇报提速了多少。
```

**P2-4 显示器外壳用插画**

## 合并版：从零描述这个项目

以后想让 AI 从头理解或复刻这个项目，可以用这一段：

```
为 Mili《world.search(you);》制作一支 1920×1080、60fps 的同人 MV，角色是《吉星派对》的邦妮（No.006，银发、深灰宽檐帽、粉紫眼睛，"毒苹果"）和芬妮（No.007，金发、白帽配棕褐帽带、蓝眼睛、藏青外套、红领结，爱变装、会解析魔法）。
剧情：天王落之后芬妮失踪，邦妮立案搜索。歌词一遍遍假设"如果你变成了某样东西"，片中把每一次假设都当作一个候选形态去检索比对，匹配度越来越接近，但结尾的搜索仍未完成，案件保持 OPEN。
画面载体是一条显示器进化时间线，每章换一代：琥珀单色 CRT → EGA 16 色 → 特丽珑 → CCFL 液晶 → IPS → OLED，换代本身就是转场（消磁、CRT 关机塌线、背光预热、OLED 像素逐个点亮）。
前四章参考 yym8224961/world.execute-me-ascii：程序界面、信息密集、数据填满屏幕、逐项初始化、字符打散重组成标题、两侧数据轨道、底部细频谱条和稳定的字幕区；角色用 wiki 的 20×20 像素头像，以半格字符绘制。
后三章参考 NancyLu PV：深蓝黑或纯黑底，终端窗口、逐字砸入的粗体标题、放射速度线、线框地球、黑白加单一主色的三色立绘板和点阵虚影。
歌词按段落分配：CRT 段是终端打字式字幕；找词段是满屏动态字，两个拉长的词做全屏巨字；低音段逐词大字；尾声像检索记录一样堆叠；副歌用字幕带。
用 Remotion 实现；canvas 字符引擎和 React 两层按镜头切换；所有切点吸附到小节线（138.75 BPM），关键动作吸附到具体拍点；所有画面都是时间的纯函数。
```
