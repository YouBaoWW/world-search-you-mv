【可复制的制作提示词开始】

请使用 Remotion 制作 Mili《world.search(you)》的角色同人 MV，主角为《吉星派对》的邦妮与芬妮。画面设计、剧情、文字动画和节奏需要构成一支完整 MV。最终交付可继续编辑的源码、素材与一份 1920×1080、60fps 的 MP4 成片。

一、核心叙事
天王落之后芬妮失踪，邦妮通过终端立案，持续检索并尝试找回她。把歌曲中不同事物的假设，转化为系统里的“候选形态”：桌子、茄子、猫、牛排、花、人、无法确定的碎片、狗、番茄。每个候选出现时显示对应图形、形态名称和匹配度，逐步接近又不断否定。
故事从冰冷的数据调查，推进到记忆、失联、递归检索、隔着屏幕伸手和留下的放大镜。结尾出现一个接近匹配但尚未验证的芬妮结果，案件停在 OPEN，保留搜索未完成的开放结局。

二、整体结构与显示器进化
全片约 4 分 55 秒，采用七章、二十二个镜头：
立案 → 卷宗 → 搜索 → 天王落 → 解析 → 深层检索 → 结案？
显示设备随叙事依次进化：
琥珀单色 CRT → EGA 16 色 CRT → 特丽珑彩色 CRT → CCFL 液晶 → IPS → OLED。
设备换代既是美术变化，也是转场本身。采用消磁波纹、CRT 关机塌成横线和亮点、背光预热、OLED 像素逐块点亮等效果。
保持同一终端系统和案件编号的连续感，让技术迭代成为深入搜索的视觉线索。

三、前半段：字符终端与 CRT
0:00 至约 2:18.7，以 Canvas 字符网格为主体。画面包含：
开机自检、进度条故障、十六进制数据、案件卷宗、检索指令、角色档案、左右数据轨道、扫描雷达、线索地图、足迹、坠星、最后一张照片、心电图和失联信息。
角色使用提供的 20×20 像素头像，以半格字符／色块方式表现，并支持逐行显影、数据转色块、损坏、乱码和溶解。
显示器需要有对应年代的机壳、扫描线、玻璃曲面、荧光辉光、色彩限制及适量噪点。CCFL 阶段呈现稍抬升的黑位和背光质感。
信息丰富，但人物、候选卡、两侧数据轨道和底部中英字幕必须分区清楚，互不遮挡。
标题段安排指令输入、回车、字符打散重组、标题定格和坠落出画。

芬妮：黑、白与金色 #FFC24A。

六、人物特效
立绘与同色斜切色带一起滑入，根据人物所在侧设置正确朝向。
芬妮的回声由正式立绘的亮度采样成金色 . : + # 字符。虚影采用约 80 列采样，以密度、亮度和闪烁变化表现从断续到逐渐恢复。使用 SVG 文字行等可稳定被全片动态模糊捕获的方式绘制。
撕裂表现为横向切片错位，故障强度随剧情上升，在深层检索附近增强，在最终副歌回落。

七、歌词与文字 PV
读取提供的 LRC，保留原英文与时间轴，并支持同时间戳中文。当前工程数据为 74 句。
歌词从数据文件加载，不写死在场景代码里。
根据段落切换以下呈现方式：
1. 早期终端段：底部打字式字幕，关键短句用 CRT 块字。
2. 找词段：不同大小的单词按节奏砸入，部分词用粉紫强调；背景压暗并隐藏干扰阅读的聊天窗口。
3. 拉长的短句：全屏巨字，配速度线、轻微旋转回正和色闪。
4. 深层检索与最终副歌：较稳定的字幕带，让画面承担叙事。
5. 低音段：黑底、单词逐个放大出现，使用模糊到清晰的过渡，保留低调的整句提示和中文。
6. 尾奏：像检索日志一样堆叠，新句清楚，旧句缩小、变暗，并控制数量以避免遮挡结果卡。
各样式都需要有相应中文字幕位置，兼顾手机观看。
逐词动画可按当前实现，在每句前 75% 时长内分配，再吸附到八分音符；不要把这种近似节奏分配描述为已经完成真实演唱词级强制对齐。

八、节拍与关键事件
采用 138.75 BPM，第一拍位于 0.35 秒。
定义小节函数 B(n) = 0.35 + n × 4 × 60 / 138.75。
镜头切点及重要事件使用小节或拍点表示，镜头内动画由相对时间插值。
保留以下关键节点：
B(24)：开场标题锁定。
B(46)：分屏中的芬妮开始溶解。
B(67)：坠星撞击；花歌词开始时先由候选卡预示，撞击后迅速生长实体花。
B(77)：心电图归零。
B(80)、B(83)、B(86)：SEARCH / PARSE / CONFIRM。
B(97) 至 B(101)：五次苹果命中防火墙。
B(135)：最终副歌白闪。
B(152)：最后搜索指令开始输入。
B(155)：回车。
B(156)：出现未验证的唯一结果。
B(167)：主体淡出。
B(168)：片尾开始。
不要为了改变视觉时长而随意破坏音乐切点。

九、全片动态模糊
全片启用真正的子帧时间采样：180° 快门角，每个输出帧 4 次采样。
覆盖镜头运动、人物入场、文字运动、字符画和转场，静止画面保持清晰。时间计算必须位于采样子树内部。
音轨与音频数据加载放在采样视觉层之外，防止声音重复或偏移。
Canvas 采样需要独立保存各子帧结果，避免多个画布竞争同一个全局绘制目标；透明素材和 SVG 点阵也要进入相同采样流程。

十、工程与输出
使用 Remotion 管理整片，前半段 Canvas 字符引擎、后半段 React/SVG 按镜头调度。
所有画面由时间 t 确定，支持任意跳帧与并发渲染；随机视觉变化使用确定性的 hash，不依赖 Math.random、Date 或上一帧状态。
片长根据输入音轨自动计算。正式输出为：
1920×1080、60fps、H.264 MP4、yuv420p、BT.709 limited range，附 AAC 双声道音轨。
使用本机 Chrome 或 Edge 渲染，支持 CHROME_PATH。全片画幅保持 scale=1；需要小尺寸审片图时，先完整捕获，再缩放。
先渲染相关关键帧和短片，检查人物朝向、帽子和手部、字幕避让、候选卡、点阵、动态模糊及转场，再输出整片。
最终检查分辨率、帧率、色彩标签、音频轨及完整解码，交付视频和可继续修改的工程。
